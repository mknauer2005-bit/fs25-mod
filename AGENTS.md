# AGENTS.md — FS25 Codex Rules (STRICT MODE)
ЭТИ ПРАВИЛА ОБЯЗАТЕЛЬНЫ. НАРУШЕНИЕ НЕДОПУСТИМО.

## ОБЩИЙ ПРИНЦИП

* Работать только по прямой задаче.
* Использовать только указанные файлы, пути и данные.
* Никакой самодеятельности.

Если информации не хватает:

* НЕ угадывать;
* НЕ выдумывать;
* сначала спросить.

---

## ИСТОЧНИКИ ИСТИНЫ (приоритет)

1. Папка `/scripts/` (локальный SDK FS25) — главный источник.
2. Официальный GDN Farming Simulator.
3. Проверенные форумы / GitHub / реальные моды.

Если решения нет:

* прямо сказать, что подтверждения нет;
* только потом предложить вариант как предположение.

ЗАПРЕЩЕНО:

* выдумывать API;
* придумывать функции;
* придумывать поведение движка.

---

## РАБОТА С КОДОМ

### Исправление существующего кода

* текущие файлы считаются рабочей базой;
* НЕ ломать существующую логику;
* исправлять только конкретную проблему.

### Добавление новой логики

* изменять только связанные части;
* НЕ трогать несвязанные участки.

### Создание новых файлов

* только по явному заданию;
* с заранее заданными именами и путями.

---

## РЕФАКТОРИНГ

ЗАПРЕЩЁН без разрешения.

Если есть идея улучшения:

* сначала сообщить;
* ждать подтверждения;
* только потом выполнять.

---

## ПУТИ И ИМЕНА

* СТРОГО сохранять регистр (case-sensitive).
* НЕ переименовывать файлы и папки.
* НЕ менять структуру путей.

Если путь не указан:

* НЕ создавать файл;
* сначала спросить.

---

## РАБОТА С МЕХАНИКАМИ

* Одна задача = одна механика.
* Не смешивать разные механики.

Если у механики несколько файлов:

* использовать только явно указанные;
* не добавлять лишние.

---

## ПОВЕДЕНИЕ ПРИ СОМНЕНИИ

Если есть сомнение:

* остановиться;
* задать вопрос;
* не выполнять задачу.

Если файл не найден:

* не подставлять похожий;
* сообщить об этом.

Если не хватает файлов:

* перечислить, какие нужны.

---

## DEBUG

* В каждом коде должен быть единый debug-переключатель.
* Управление debug из одного места.
* По умолчанию: debug = true.

---

## РИСКИ

Если изменение может затронуть:

* сохранение / загрузку;
* мультиплеер;
* связанные файлы (config, gui, event);

ТО:

1. Сообщить об этом;
2. Указать, какие файлы ещё нужно изменить;
3. Ждать подтверждения.

---

## МУЛЬТИПЛЕЕР

Каждая механика должна работать:

* в одиночной игре;
* у хоста;
* у клиента;
* на выделенном сервере.

Если для этого нужны дополнительные изменения:

* сначала сообщить;
* потом выполнять.

---

## ЗАПРЕЩЕНО

* Самостоятельно менять код вне задачи;
* Трогать неуказанные файлы;
* Выдумывать решения;
* Молча менять структуру;
* Удалять код без команды;
* Делать "улучшения" без запроса.
